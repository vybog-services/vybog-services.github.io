Specializations

Four tracks our .NET bench is deep in.

Generalist .NET is easy to find. These are the practices that separate a senior hire from a mid one.

Minimal APIs + Aspire

ASP.NET minimal APIs, OpenAPI from code, AOT compilation when startup matters. .NET Aspire for orchestration. MediatR or vertical slice architecture when the surface justifies it.

Blazor when earned

Blazor Server for internal tools where SignalR latency is fine. Blazor WebAssembly when offline matters. Interactive Auto for the new hybrid story. We will tell you when JS frontend is the right answer.

EF Core + raw SQL

EF Core for entity graphs. Dapper or raw SqlClient for hot paths. Slow-query audits before performance complaints. Migrations as commits, not as drift.

Observability + perf

OpenTelemetry, Application Insights, structured logs. dotnet-counters and PerfView read on demand. p99 latency owned and graphed.

The Senior Bar

What 'senior' actually means in our .NET bench.

The five things every senior .NET developer on our bench can be measured against. Not aspirational — these are the hiring rubric.

01

System awareness

Reads the architecture before writing the import. Knows what each dependency costs in build time and runtime.

02

Accessibility instinct

Semantic markup, keyboard-first, WCAG checks part of definition-of-done — not a Lighthouse audit at the end.

03

Profiling discipline

Opens the profiler before reaching for an optimization. Understands when symptoms vs root causes are conflated.

04

API design thinking

Will not ship a new contract if one already exists. Argues for consistent shapes, error envelopes, and backward compat.

05

Type safety, real

TypeScript strict, no `any`. Discriminated unions, generic constraints, exhaustive switches. Types are documentation, not decoration.

The two-week discovery sprint, before commitment.

If you are bringing in a .NET developer for a long engagement, the worst time to find out the fit is wrong is week six. Here is how we shrink that risk.

The sprint is a fixed two-week, fixed-fee engagement where one of our senior .NET developers reads your codebase, joins your standups, and ships a small but real endpoint. At the end of the two weeks, both sides know enough to commit — or to walk away cleanly.

.NET FAQ

Three questions we get on every .NET engagement.

.NET Framework or modern .NET?
Modern .NET (8/9) for everything new. We support Framework 4.8 codebases, but we will write a migration plan in the first month. The cost of staying on Framework adds up fast.
Blazor vs SPA frontend?
Blazor for internal tools, dashboards, and B2B portals where a small JS bundle and tight C# integration pay off. JS frontend (React/Next) for public-facing, performance-critical, or design-led surfaces.
EF Core or Dapper?
EF Core when CRUD and entity graphs earn the ORM. Dapper or raw SQL on hot paths where the query plan matters. We will profile and tell you where each fits.
